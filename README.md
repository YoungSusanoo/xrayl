# xrayl

Telegram-бот с личным словарём. PostgreSQL, команда миграций и функция
сохранения слова со значением готовы;
подключение хранилища к сценариям бота — следующий этап.

## Локальная база

Нужны Go версии из `go.mod` и Docker Compose.

Если `.env` ещё нет, скопируйте `.env.example` в `.env`. Укажите `BOT_TOKEN`
для запуска бота, а для базы — `POSTGRES_USER`, `POSTGRES_DB`,
`POSTGRES_PASSWORD`, `POSTGRES_PORT` и `DATABASE_URL`.
Пароль в `DATABASE_URL` должен совпадать с `POSTGRES_PASSWORD`; специальные
символы логина и пароля в URL нужно кодировать. Переменные окружения имеют
приоритет над `.env`; файл `.env` необязателен.

```sh
docker compose config --quiet
docker compose up -d --wait
docker compose ps
```

База доступна только на `127.0.0.1`, по умолчанию на порту 5432.
Данные хранятся в volume `postgres_data`, смонтированном в
`/var/lib/postgresql` для PostgreSQL 18. Обычный `docker compose down`
сохраняет volume. Изменение `POSTGRES_*` после первого запуска не меняет
существующие роли, пароли и базы — эти настройки применяются при
инициализации пустого volume.

## Миграции

Команды выполняются из корня проекта и используют `DATABASE_URL`:

```sh
go run ./cmd/migrate status
go run ./cmd/migrate up
```

Для отката одной последней миграции:

```sh
go run ./cmd/migrate down
```

Начальная миграция при откате удаляет таблицы словаря вместе с данными.
Для проверки отката используйте отдельную тестовую базу ниже.

SQL-файлы находятся в `internal/storage/postgres/migrations` и встраиваются
в мигратор при сборке. Goose хранит применённые версии в таблице
`goose_db_version`. Повторный `up` не применяет уже выполненные миграции.
Команды миграций используют advisory lock, чтобы не менять схему одной
базы одновременно, и ограничены временем выполнения в одну минуту.

## Добавление слова и значения

Миграция `0002` добавляет функцию PostgreSQL. Пример вызова после `migrate up`:

```sql
SELECT word_id, meaning_id, meaning_created
FROM add_word_meaning(1001, 'Book', 'Printed work');
```

Функция одной атомарной операцией создаёт пользователя при отсутствии,
находит или создаёт его слово и добавляет значение. `user_id` соответствует
Telegram user ID. Слова сравниваются без учёта регистра; первоначальное
написание существующего слова сохраняется. `btrim` убирает обычные пробелы
по краям входных текстов. `NULL` и пустые после обработки тексты отклоняются
с SQLSTATE `22023`.

Определения одного слова у одного пользователя уникальны без учёта регистра
и крайних пробелов. При повторе возвращаются существующие идентификаторы
и `meaning_created = false`; при добавлении — `true`. Уникальный индекс
защищает от дублей и при прямой записи в таблицу. Конкурентные вызовы
поддерживаются при стандартном уровне изоляции `READ COMMITTED`.

Если в базе уже есть повторные определения, миграция `0002` завершится
ошибкой без удаления данных. Откат этой миграции удаляет функцию и индекс,
сохраняя записи. Интеграция с API словаря будет отдельным этапом.

## Проверки

Обычные тесты не требуют PostgreSQL:

```sh
go test -race ./...
go vet ./...
go build ./...
```

Интеграционные тесты используют отдельный Compose-проект и базу
`xrayl_test` на порту 55432. Контейнер хранит данные в памяти; при его
удалении тестовые данные исчезают. База проекта и её volume не затрагиваются.

```sh
docker compose -p xrayl-migrations-test -f compose.test.yaml up -d --wait
TEST_DATABASE_URL='postgres://xrayl:xrayl_test@127.0.0.1:55432/xrayl_test?sslmode=disable' \
  go test -race -tags integration -count=1 ./...
docker compose -p xrayl-migrations-test -f compose.test.yaml down
```

При занятом порту задайте `POSTGRES_TEST_PORT` для тестового Compose и
измените порт в `TEST_DATABASE_URL`. Тесты требуют явный
`TEST_DATABASE_URL`, создают отдельную схему для каждого теста и удаляют
только собственные схемы. Проверяются применение/откат/повторное
применение миграции, уникальность без учёта регистра, принадлежность
записей пользователю, каскадное удаление и откат транзакции. Для функции
добавления проверяются нормализация, повторные определения, неверные
аргументы, атомарность, конкурентные вызовы и миграция существующих данных.

Для запуска бота:

```sh
go run .
```

Бот пока не обращается к PostgreSQL и не выполняет миграции автоматически.
