# xrayl

Telegram-бот для изучения английского языка с личным словарём.
Команда `/addword` получает определения из FreeDictionaryAPI.com и сохраняет
выбранное значение и его синонимы в PostgreSQL.

## Локальная база

Нужны Go версии из `go.mod` и Docker Compose.

Если `.env` ещё нет, скопируйте `.env.example` в `.env`. Укажите `BOT_TOKEN`
для запуска бота, а для базы — `POSTGRES_USER`, `POSTGRES_DB`,
`POSTGRES_PASSWORD`, `POSTGRES_PORT` и `DATABASE_URL`.
Пароль в `DATABASE_URL` должен совпадать с `POSTGRES_PASSWORD`; специальные
символы логина и пароля в URL нужно кодировать. Переменные окружения имеют
приоритет над `.env`; файл `.env` необязателен.

```sh
docker compose config --quiet
docker compose up -d --wait
docker compose ps
```

База доступна только на `127.0.0.1`, по умолчанию на порту 5432.
Данные хранятся в volume `postgres_data`, смонтированном в
`/var/lib/postgresql` для PostgreSQL 18. Обычный `docker compose down`
сохраняет volume. Изменение `POSTGRES_*` после первого запуска не меняет
существующие роли, пароли и базы — эти настройки применяются при
инициализации пустого volume.

## Миграции

Команды выполняются из корня проекта и используют `DATABASE_URL`:

```sh
go run ./cmd/migrate status
go run ./cmd/migrate up
```

Для отката одной последней миграции:

```sh
go run ./cmd/migrate down
```

Начальная миграция при откате удаляет таблицы словаря вместе с данными.
Для проверки отката используйте отдельную тестовую базу ниже.

SQL-файлы находятся в `internal/storage/postgres/migrations` и встраиваются
в мигратор при сборке. Goose хранит применённые версии в таблице
`goose_db_version`. Повторный `up` не применяет уже выполненные миграции.
Команды миграций используют advisory lock, чтобы не менять схему одной
базы одновременно, и ограничены временем выполнения в одну минуту.

## Добавление слова и значения

Миграция `0002` добавляет функцию PostgreSQL. Пример вызова после `migrate up`:

```sql
SELECT word_id, meaning_id, meaning_created
FROM add_word_meaning(1001, 'Book', 'Printed work');
```

Функция одной атомарной операцией создаёт пользователя при отсутствии,
находит или создаёт его слово и добавляет значение. `user_id` соответствует
Telegram user ID. Слова сравниваются без учёта регистра; первоначальное
написание существующего слова сохраняется. `btrim` убирает обычные пробелы
по краям входных текстов. `NULL` и пустые после обработки тексты отклоняются
с SQLSTATE `22023`.

Определения одного слова у одного пользователя уникальны без учёта регистра
и крайних пробелов. При повторе возвращаются существующие идентификаторы
и `meaning_created = false`; при добавлении — `true`. Уникальный индекс
защищает от дублей и при прямой записи в таблицу. Конкурентные вызовы
поддерживаются при стандартном уровне изоляции `READ COMMITTED`.

Если в базе уже есть повторные определения, миграция `0002` завершится
ошибкой без удаления данных. Откат этой миграции удаляет функцию и индекс,
сохраняя записи.

Миграция `0003` добавляет `meanings.synonyms` типа `TEXT[]` и вариант функции
с четырьмя аргументами:

```sql
SELECT word_id, meaning_id, meaning_created
FROM add_word_meaning(1001, 'Book', 'Printed work', ARRAY['Volume', 'Tome']);
```

Синонимы нормализуются в БД: крайние пробелы удаляются, пустые элементы и
`NULL` исключаются, повторы без учёта регистра убираются с сохранением
первого написания и порядка. При повторе определения переданный массив
заменяет прежний, в том числе пустой массив очищает список.
`meaning_created` при таком обновлении равен `false`.

Трёхаргументный вызов совместим с прежним: создаёт значение с пустым
списком и сохраняет синонимы при повторе. То же поведение у SQL `NULL`
в четвёртом аргументе. Go-хранилище передаёт отсутствующий список как
пустой массив, чтобы явно очищать устаревшие синонимы.

Откат `0003` сохраняет слова и определения, удаляет синонимы и восстанавливает
исходную трёхаргументную функцию. Начальную миграцию и миграцию `0002`
не изменяли.

## Добавление через Telegram

Перед запуском бота примените миграции:

```sh
go run ./cmd/migrate up
go run .
```

Для запуска обязательны `BOT_TOKEN` и `DATABASE_URL`. Бот проверяет
подключение к БД с тайм-аутом пять секунд. Миграции автоматически не
выполняются. Соединения закрываются при SIGINT или SIGTERM.

1. Отправьте `/addword` и введите английское слово.
2. Получите нумерованный список определений с частями речи.
3. Отправьте номер нужного определения.
4. Получите карточку сохранённого значения и его синонимов.

Сохраняются только синонимы самого определения (`Definition.Synonyms`).
Синонимы группы значений автоматически не переносятся. При повторном
добавлении определения его идентификатор сохраняется, а синонимы обновляются.
Часть речи, примеры, антонимы, ссылки и лицензии в БД не записываются;
сведения об источниках при наличии показываются из текущего ответа API.

`/cancel` отменяет текущий диалог; `/addword` начинает ввод заново.
После ошибки словаря можно повторить ввод слова. После ошибки БД можно
повторить номер без нового запроса к словарю. Длинные списки и карточки
делятся на сообщения до 3000 единиц UTF-16 с сохранением полного текста
и общей нумерации. Неподтверждённые диалоги теряются при перезапуске.

Диспетчер сохраняет маршрутизацию по `(chatID, userID)` и общий mutex на
время обработки сообщения. Пока один диалог выполняет запрос к словарю
или БД, остальные обработчики ждут освобождения mutex. Тайм-аут запроса к словарю и сохранения —
пять секунд; каждый запрос отправки сообщения тоже ограничен пятью секундами.

## Просмотр сохранённых слов

После применения миграции `0004` команда `/words` показывает личный словарь
по алфавиту без учёта регистра. Каждое слово выводится один раз, даже если
сохранено несколько его значений. Исходное написание слова сохраняется.

На странице до 20 слов, номера на каждой странице начинаются с 1.
`/next` и `/prev` переключают страницы. Отправьте номер, чтобы получить все
сохранённые определения выбранного слова и синонимы каждого определения.
После этого можно выбрать другой номер с той же страницы.

`/words` открывает первую страницу заново, `/cancel` завершает просмотр,
а `/addword` заменяет его добавлением слова. Пустой словарь сопровождается
подсказкой `/addword`. Данные читаются только из PostgreSQL, без запроса к API.
Списки и карточки делятся на сообщения без обрезания текста.

Страница хранится в сессии вместе с соответствием номеров словам. При ошибке
загрузки другой страницы прежний список остаётся доступным; при ошибке
загрузки значений можно повторить номер. Загруженная страница сохраняется
до отправки сообщения, в том числе при тайм-ауте Telegram. Изменения словаря
отражаются при следующей загрузке страницы или повторном `/words`.

Миграция `0004` добавляет функции чтения с `SECURITY INVOKER`:

```sql
SELECT word_id, word FROM list_words(1001, 21, 0);
SELECT meaning_id, definition, synonyms FROM list_word_meanings(1001, 123);
```

Обе функции ограничивают выборку пользователем. Порядок слов —
`lower(text), id`, значений — `id`. Для страниц `limit` должен быть положительным,
`offset` — неотрицательным; обязательные аргументы не допускают `NULL`.
Неверные аргументы отклоняются с SQLSTATE `22023`. Запросы хранилища
ограничены пятью секундами. Откат миграции удаляет только функции чтения.

## Клиент английского словаря

`internal/dictionary/freedictionaryapi` предоставляет клиент
[FreeDictionaryAPI.com](https://freedictionaryapi.com).
Он возвращает статьи с частями речи, определениями, примерами, синонимами и
антонимами в типах пакета `internal/dictionary`. Списки синонимов и антонимов
сохраняются отдельно для группы значений и для каждого определения.

```go
client := freedictionaryapi.NewClient(
    freedictionaryapi.BaseURL,
    &http.Client{},
)
entries, err := client.Lookup(ctx, "book")
```

Если HTTP-клиент не передан (`nil`), используется `http.DefaultClient`.

Входное слово очищается от крайних пробелов и передаётся отдельным сегментом
URL. Вызов ограничен пятью секундами и учитывает более раннюю отмену
контекста. Размер ответа ограничен 2 МиБ. Сначала сохраняется регистр ввода;
если API вернул пустой список статей, выполняется один поиск в нижнем регистре
в пределах того же тайм-аута. Сетевые и HTTP-ошибки не повторяются.
Кеширование не выполняется. Вложенные определения разворачиваются в порядке
ответа; несколько примеров объединяются переводами строк.

Ошибки `dictionary.ErrInvalidWord`, `ErrNotFound`, `ErrRateLimited` и
`ErrInvalidResponse` проверяются через `errors.Is`. Остальные HTTP-ошибки
возвращаются как `*dictionary.HTTPError` со статусом, доступным через
`errors.As`; сетевые ошибки и ошибки контекста сохраняются в цепочке ошибок.

Пустой список `entries` означает отсутствие слова. HTTP 404 сам по себе
не считается отсутствием слова: возвращается `*dictionary.HTTPError`.

Ссылка на исходную статью Wiktionary и лицензия при наличии передаются в
результате запроса вместе со ссылкой на FreeDictionaryAPI.com для атрибуции.
Они показываются в сообщениях бота и не сохраняются в БД.
Клиент не сохраняет данные в PostgreSQL; сохранение выполняет
сценарий `/addword` через хранилище. Тесты клиента используют локальные HTTP-серверы
и не требуют доступа к внешнему API или PostgreSQL.

## Проверки

Обычные тесты не требуют PostgreSQL:

```sh
go test -race ./...
go vet ./...
go build ./...
```

Интеграционные тесты используют отдельный Compose-проект и базу
`xrayl_test` на порту 55432. Контейнер хранит данные в памяти; при его
удалении тестовые данные исчезают. База проекта и её volume не затрагиваются.

```sh
docker compose -p xrayl-migrations-test -f compose.test.yaml up -d --wait
TEST_DATABASE_URL='postgres://xrayl:xrayl_test@127.0.0.1:55432/xrayl_test?sslmode=disable' \
  go test -race -tags integration -count=1 ./...
docker compose -p xrayl-migrations-test -f compose.test.yaml down
```

При занятом порту задайте `POSTGRES_TEST_PORT` для тестового Compose и
измените порт в `TEST_DATABASE_URL`. Тесты требуют явный
`TEST_DATABASE_URL`, создают отдельную схему для каждого теста и удаляют
только собственные схемы. Проверяются применение/откат/повторное
применение миграции, уникальность без учёта регистра, принадлежность
записей пользователю, каскадное удаление и откат транзакции. Для функции
добавления проверяются нормализация, повторные определения, неверные
аргументы, атомарность, конкурентные вызовы и миграция существующих данных.
Также проверяются обновление и очистка синонимов, совместимость функций,
откат миграции и полный сценарий `/addword` с локальными серверами словаря
и Telegram и отдельной тестовой PostgreSQL. Для `/words` проверяются порядок,
страницы, изоляция пользователей, несколько значений одного слова, отмена,
переключение сценариев и отсутствие запросов к внешнему словарю при просмотре.
